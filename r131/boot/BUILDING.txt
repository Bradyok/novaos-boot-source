Building the RK3399 boot chain of this release
==============================================

Everything this needs besides the tools below is in this directory. src/ holds the complete source
tree of every component with our patches already applied (each lane's patches/ has them as patches,
to read); FACTS.env names the upstream commit of each tree, and src/UPSTREAM.sha256 every file of it
that is upstream's unchanged. build.sh builds in a copy of each tree. Nothing is downloaded.

  bash build.sh --toolchains DIR [--out DIR] [--work DIR] [--lanes ...] [--families ...]
                [--stage-b FAMILY=stage-b.img ...] [--check]

Step by step (Linux x86_64, in the directory that holds boot/)
--------------------------------------------------------------
  1. The host tools (below); on Debian or Ubuntu:
       sudo apt install build-essential bc bison flex gawk libssl-dev uuid-dev libgnutls28-dev \
           python3-dev python3-setuptools python3-pyelftools swig gcc-aarch64-linux-gnu
  2. The build, which needs no network and compares what it makes with expected.sha256:
       bash boot/build.sh --check
     It ends with "build.sh: N of N binaries are the shipped bytes"; the binaries are in boot/out/.
     The recovery images are rebuilt only given the release's stage-B image of each family
     (--stage-b dho900=FILE --stage-b mho900=FILE); without them they are listed as not rebuilt.

Lanes
-----
  uboot-proper  U-Boot proper alone, per family (dho900, mho900) and flavor (kexec-test, chainload):
                u-boot.bin, u-boot.dtb. And per family (dho900, mho900)
                chain/recovery-uboot-chain.img, the image the scope's stock boot loader starts from
                `recovery`: the chainload u-boot.bin as its kernel, the release's stage-B kernel (as
                one lz4 -9 frame), DTB and initramfs as a FIT after it. install/ holds the scripts
                that pack it (tools/boot/dho900_uboot_chain.py with rk_bootimg.py and
                tools/kernel/tu15_fdt.py) and parm-cmdline.txt, the command line of the card's
                partition table that the stock boot loader adds; build.sh runs them given the
                release's stage-B image of each family (--stage-b FAMILY=FILE; FACTS.env names its
                sha256).

Compilers (the exact ones; another compiler builds working binaries, not the same bytes)
---------
  uboot-proper: the cross toolchain aarch64-linux-gnu-* of the build host (Ubuntu 26.04.1 LTS):
      aarch64-linux-gnu-gcc (Ubuntu 15.2.0-16ubuntu1) 15.2.0
      GNU ld (GNU Binutils for Ubuntu) 2.46
    (CROSS_COMPILE overrides the prefix; build.sh warns when the version differs)

What comes out the same
-----------------------
  With these compilers every binary in expected.sha256 is the shipped one byte for byte, wherever the
  directory is: no binary holds a build path, and SOURCE_DATE_EPOCH (FACTS.env) is every timestamp in
  them. build.sh ends by comparing them (--check makes a difference an error). The ELF files u-boot
  and the linker maps a build also leaves are not in the list: they name the compiler's install
  directory, and nothing of them ships.

Not here, on purpose
--------------------
  rkdeveloptool (a PC tool that sends the Maskrom images over USB): it is in no binary that ships.
  The kernel inside the recovery image is the kernel source bundle's.
